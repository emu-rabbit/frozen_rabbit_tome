# 姊妹專案參考規範 (Sister Project Reference)

## 1. 專案血緣
本專案 **`frozen_rabbit_tips` (採集策略工具)** 與同級目錄下的 **`frozen_rabbit_workshop` (工坊管理工具)** 為姊妹專案。
- **關係**：兩者雖然功能獨立，但共享相同的設計語彙、核心思想與部分資料結構。
- **目標**：確保使用者在切換兩個工具時，能感受到一致的視覺體驗與操作邏輯。

## 2. 視覺風格同步 (Visual DNA)
Agent 在設計 UI 或編寫 CSS 時，必須優先參考 `frozen_rabbit_workshop` 的實現方式：
- **配色系統**：
    - **主色 (Soft Green)**：以 `#52a890` 為核心的綠色系。
    - **背景色**：淺色模式使用 `soft-green-50` (`#e8f5e9`)，深色模式使用 `slate-950` (`#020617`)。
- **設計元素**：
    - 使用圓角、細微的陰影以及流暢的微動畫。
    - 捲軸樣式、按鈕樣式應保持高度一致。
- **設計工具**：若專案使用 Tailwind CSS，應複製 `frozen_rabbit_workshop` 的 `tailwind.config.js` 中的顏色定義。

## 3. 資料與邏輯架構
- **資料格式**：若涉及 FFXIV 的物品 (Items)、節點 (Nodes) 或時間格式，應優先查看 `frozen_rabbit_workshop/src/types` 中的定義，避免重複定義不相容的 Schema。
- **語系同步**：I18n 的關鍵字（如：採礦工、園藝工、GP、獲得力等）必須與姊妹專案完全一致。

## 4. Agent 行為準則
- **主動跨專案檢索**：當接到涉及 UI 設計或重大資料結構變更的任務時，Agent 應主動使用 `ls` 或 `view_file` 檢視姊妹專案的相關實現。
- **一致性維護**：在實作新功能時，應思考「如果這個功能在 workshop 專案中，它會長什麼樣子？」，並以此為基準進行設計。

## 5. 注意事項
- 雖然外觀相似，但本專案側重於「策略演算」，而 workshop 側重於「資料管理」。請勿為了追求一致性而犧牲了本專案特有的演算效能或工具便利性。
